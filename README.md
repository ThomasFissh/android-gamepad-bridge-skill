# 41 配置安卓手柄 · 安卓手柄桥接

**作者：李逊 · 技能 v1.1.0 · App v1.7.0 · MIT License**

保留手柄原装 2.4G 接收器，在安卓掌机上配置外接手柄、模拟器全局映射，以及只认内置手柄的游戏兼容。本项目包含可供 AI 助手使用的 `SKILL.md`、桥接 App 源码和通用名称 APK。

**此前功能基线真机验证：Retroid Pocket 6（RP6）＋已验证的 2.4G USB 接收器。** 这不是所有安卓机器通用的免 root 驱动。普通模式取决于该系统开放的 USB/uinput 能力；内置兼容模式使用机主授权的既有厂商 root 服务。

## 下载与使用 App

在 [Releases](https://github.com/ThomasFissh/android-gamepad-bridge-skill/releases/latest) 下载 `Android-Gamepad-Bridge-1.7.0.apk`，可用同页 `SHA256SUMS.txt` 校验。此公开版已将显示名称、包名及虚拟设备名称通用化，保留既有 USB 协议和授权逻辑，并使用独立签名。改名版已完成编译和静态检查，尚未重新做真机操作验收。最低 Android 8.0/API 26；满足版本要求不代表当前 ROM 一定支持。

1. 接好扩展坞与待验证手柄的 USB 接收器，打开手柄，保持 2.4G 模式。
2. 安装并打开“安卓手柄桥接”，允许系统请求的 USB 访问。
3. **普通游戏/模拟器**：不勾选内置兼容，点“启动桥接”。确认实时按键、摇杆和扳机显示后，回桌面打开游戏。
4. **RP6 的《死亡细胞》等只认内置的游戏**：了解并接受下方授权机制后，勾选“内置手柄兼容”，点启动，再启动游戏。
5. 不用时在 App 点“停止桥接”。切换模式后再点启动；模拟器可能需要在全局玩家1设置中追加外接映射。

此前功能基线已通过 RP6 重启后不开无线调试、不启动 Shizuku、不连接电脑，直接打开 App、点启动并操作《死亡细胞》的实测。下表属于该功能基线的证据，不能替代此改名构建的真机复测。USB 授权是否需要再次确认由设备系统和接收器连接状态决定。

**Select＋Start** 会发送 Android 返回；部分模拟器需要另外配置原生菜单快捷键。已验证接收器对应的 M1/M2 在本次出厂状态采样中没有独立报告，本项目没有将它们映射为返回/Home。

## 像素输入测试界面

新版提供双摇杆实时位置与坐标、按键高亮、LT/RT 行程、观察设备选择、统计清空和详细读数；启动、停止、兼容模式、采样、震动功能保留。原生 Canvas/Vector 绘制，不依赖网络服务。

已经被 Android 识别为 GAMEPAD/JOYSTICK 的手柄，可以直接使用输入观察层；内置兼容模式下若外接输入与内置共用一个系统控制器，页面会说明共用关系。测试页按键只显示状态，避免误触启动/停止，系统返回键可退出。清空统计不会校准或修改手柄。

界面模块可继续移植到其他机型，但它不会让当前 USB 协议或 RP6 厂商授权自动通用。具体模块、备份/覆盖恢复和验收方法见 [输入测试界面与移植](41-configure-android-gamepad/references/controller-ui.md)。

当前通用名称构建已通过源码编译、输入状态测试、签名与公开内容扫描。原设备界面版完成按下/松开、两杆、扳机行程、归中和失焦清理的构造事件测试；这些属于显示接入测试，不能写成实体手柄或游戏实按。本公开包未重新在实体设备安装/重启测试，历史功能基线的游戏结果仍单独记录。

## 两部分与适配范围

| 部分 | 做什么 | 当前条件 |
|---|---|---|
| 不需要内置手柄兼容 | 读取接收器报告，输出 Android 虚拟手柄，追加模拟器全局按键 | 普通 App 的 USB 权限，且系统允许该 App 创建 uinput 手柄；RP6 已验证 |
| 需要内置手柄兼容 | 将接收器事件提交到已有内置控制器，让只认内置的游戏接收输入 | **机器的 root 入口由机主提供并授权**；当前 APK 仅适配已验证 RP6 厂商入口 |

没有 root 入口的其他机器，仍可检查普通模式；不能因为 RP6 能用就认为其内置兼容也能用。当前 App 没有通用 `su` 或 Shizuku 后端。它不会为你安装 root、解锁 bootloader、刷机或关闭 SELinux。

### 内置兼容的授权机制

RP6 设置中的“以 Root 身份运行脚本”使用厂商已有服务。本版本通过该服务确认 root 执行身份，识别唯一内置控制器，将**该单个输入节点**的所有者临时交给 App，原输入组与 `0660` 权限保留。停止时释放 App 产生的按键/轴并恢复所有者；下次运行可恢复本 App 遗留的租借状态。异常杀进程时不能保证即时恢复，退出/重启后的权限应按验收流程核对。

因此“没有额外安装 root”不等于“不使用 root 权限”。App 不批量放开输入节点，不暴露任意 root 命令接口。详细实现见 [已验证适配](41-configure-android-gamepad/references/rp6-usb-bridge.md) 和 `OemInputGrant.java`。系统更新可能改变服务和权限，需要重新验证。

### 已验证与待验证

| 项目 | 证据范围 |
|---|---|
| RP6＋指定 2.4G USB 接收器 | 普通 App 读取 USB、虚拟手柄、按键和双摇杆/扳机范围、独立启动已测试 |
| 《死亡细胞》内置兼容 | 实体方向、A/B、摇杆、返回、游戏操作及最终重启验收通过 |
| PS2 / AetherSX2 | 内置＋外接全局绑定、Select＋Start 菜单，实体操作通过 |
| RetroArch | L2＋Start 菜单，L2＋左右切存档位、上读档、下存档；内置/外接已测 |
| 3DS / Azahar 系列 | 电视镜像上下屏与遮罩、L3 切屏已测，需用户自备布局/遮罩 |
| Dolphin / DuckStation | 全局双手柄配置与界面回读；未做游戏实测 |
| 震动 | 标准模式接收器/系统路径已测；内置兼容下的游戏震动未单独验证，不能保证 |
| 其他安卓设备、接收器、ROM | 未验证；按技能先最小测试，再适配，不统一改输入权限 |

此公开版采用独立包名 `io.github.thomasfissh.androidgamepadbridge`，不会覆盖既有安装。接收器同一时间只能由一个桥接 App 使用，测试前先停止其他桥接。普通模式虚拟设备名为 `Gamepad Bridge Controller`；旧配置绑定过其他虚拟设备时需要追加新设备，保留掌机自带绑定。

App 不会自动修改所有模拟器配置；这些全局设置由技能指导助手逐软件配置，并保留掌机自带按键。

## 安装技能

在 Releases 下载 `41-configure-android-gamepad-v1.1.0.zip`，解压，将整个 `41-configure-android-gamepad` 文件夹放入助手的个人技能目录，例如 `~/.codex/skills/`。保留其中的说明、参考、源码与资源。已有同名技能时先备份再合并。

调用示例：

> 使用技能41，帮我配置这台安卓掌机的无线手柄，保留原装接收器和掌机自带按键。先识别设备与普通权限；只认内置的游戏需要兼容时，我来提供这台机器的 root 入口。常用模拟器按全局设置，完成后验证重启无需电脑。

也可以克隆仓库后使用 [技能目录](41-configure-android-gamepad/)。安装技能不会自动操作任何设备。使用者须提供自己设备的访问方式和授权，不从作者环境获取连接信息。
