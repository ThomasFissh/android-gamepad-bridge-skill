# 输入测试界面与移植

## 可复用部分

当前界面包含双摇杆实时位置/坐标、ABXY/方向/肩键/摇杆按键高亮、LT/RT 行程、观察设备选择、统计清空和详细读数。图形是原生 Canvas/Vector，保持深蓝底、薄荷绿/暖金/淡紫的像素视觉；中文用清晰系统字体。样式是已选实现，不强制未来所有 App 使用像素风。

- `PadState.java`：只保存显示状态；按下/松开、重复计数、轴值、数字/模拟扳机分离，统计清空保留当前输入，失焦/设备断开清除旧状态。它不转发、不校准、不修改键位。
- `ControllerView.java`、`PixelUi.java`：绘图与界面组件，可独立复用。
- `MainActivity.java`：筛选系统 GAMEPAD/JOYSTICK 设备并接收 KeyEvent/MotionEvent。逐设备观察，不混合多个控制器；兼容模式若与内置共用同一设备，应明确标注。测试键不触发桥接控制按钮，系统返回仍可退出。
- `BridgeService`、`VirtualPad`、`NativePad`、`OemInputGrant`：保留已稳定的协议/转发/授权实现。新机器只替换经验证需要适配的部分，不把厂商入口或固定协议当成通用能力。

## 新机型接入

先识别设备/接收器、输入来源与已获授权范围。已被 Android 识别为手柄的控制器可以直接进入输入观察层；这不需要为观察界面另加 root，也不证明 USB 桥接或游戏兼容已完成。

系统没有 gamepad 事件时，分别验证 USB 报告解析、普通 App 输出权限、虚拟设备或用户提供的内置兼容入口。不要只替换 VID/PID 就宣称适配。未知背键不生成虚假按钮结果。ABXY 按 Android 键值标注；右摇杆和触发轴按实际 MotionRange 选择 Z/RZ 或 RX/RY、LTRIGGER/RTRIGGER 或 BRAKE/GAS，保留模拟行程，不用数字阈值覆盖真实百分比。

## 只改界面与恢复

1. 保存当前 APK、源码、版本/签名、兼容勾选与服务运行状态。原地升级需同签名；私钥留在技能/公开仓库之外。
2. 在副本修改显示与事件观察层。对照桥接核心源码及可比编译结果，保留 USB 授权/启动/停止、采样、震动和外部启动语义；改名公开版另作包名/设备名/签名审查。
3. 保留旧 APK 和可覆盖恢复包。降级受限时，用原源码、同签名和更高 versionCode 生成恢复包，核对其 classes.dex 与旧包一致；不要通过卸载清数据解决恢复。
4. 整图和必要局部检查文本、焦点、遮挡及像素边界。显示测试覆盖按下/松开、两杆各方向、扳机行程与数字回退、HAT、归中、失焦/断开，测试输入不得误触启动/停止。

## 当前证据范围

原设备界面版 1.7.0 的显示状态测试与 RP6 界面事件测试通过；桥接核心四类的源码和编译字节与旧基线一致，兼容勾选与停止状态保留。本次未重新做实体手柄、游戏和冷启动验收。关联真实 Android 设备 ID 的构造测试事件仍是测试事件，不能写成实按结果。

公开版必须使用通用应用/包名、虚拟设备名、日志标签、文件名和源码标识，扫描文本/路径及 APK 资源/DEX/签名元数据。不得复制含设备专用标识的本机原包/恢复包、未去除私人标识的截图、序列号、网络地址、私人路径、日志、密钥或厂商 APK 到公开材料。保留确实需要的兼容目标及协议能力条件；诚实区分原设备版、公开改名版和其他机型的验收范围。

参考：[Android 控制器输入](https://developer.android.com/games/sdk/game-controller/controller-input)、[GamepadTest](https://github.com/jimandreas/GamepadTest)。图形与显示代码自行实现，未引入第三方桥接。

当前通用名称 APK 为 1.7.0-pixel，源码构建/状态测试通过；未在实体设备重新安装并复测该包。原设备版的界面事件结果与历史游戏验收均不可移作本 APK 的完整实测。
